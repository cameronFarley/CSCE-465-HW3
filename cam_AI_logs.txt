The tests only work if your fixed parser does two things:

Rejects input before the copy and returns non-zero. For example:
c
   if (n > BUF_SIZE) {
       fprintf(stderr, "error: %zu bytes exceeds %d-byte limit\n", n, BUF_SIZE);
       return -1;   /* make main() exit non-zero */
   }
   memcpy(buf, input, n);
Exits non-zero on a missing file.
If you '\0'-terminate buf and print it with %s, your real limit is 127, so run MAX_LEN=127 bash tests/run_tests.sh. Otherwise, print with printf("%.*s", (int)n, buf) and keep 128. The 128-byte case is exactly where an off-by-one bug would show up.

Task 4 profile (apparmor.profile)
The comments in the file map each rule to the assignment’s five requirements, which helps with report part (2). Some things to know before you run it:

Payload name. The profile allows only inbox/payload.bin. If your payload has a different name, edit that line.

DAC setup. agentlab needs Unix permissions to reach files in your home directory. AppArmor can only restrict access further; it can’t grant anything. Run this from ~/csce465-agentsec/hw3:

bash
setfacl -m u:agentlab:x  ~ ~/csce465-agentsec ~/csce465-agentsec/hw3
setfacl -m u:agentlab:rx ./legacy_log_parser ./inbox
setfacl -m u:agentlab:r  ./inbox/payload.bin
setfacl -m u:agentlab:rwx ./markers
Load and run:

bash
sudo apparmor_parser -r policy/apparmor.profile
sudo aa-status | grep legacy_log_parser
sudo -u agentlab ./legacy_log_parser inbox/payload.bin
